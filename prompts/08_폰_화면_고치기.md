# 실습③-3 같은 명세를 폰 화면으로 — 화면만 고치기 (2분)

폰 화면 테스트(`e2e-ts/mobile/`)가 빨간불이고 명세에 폰 AC 두 줄을 넣었다면, **새 대화**에서 아래를 보냅니다. 보내기 전에 두 가지를 확인하세요.
- 폰 테스트와 명세 두 줄을 **커밋해 두었나?** 테스트를 만든 직후 커밋해 두어야 `git diff` 로 AI 가 무엇을 바꿨는지만 보입니다.
- 1) 에서 띄운 `python web/app.py` 를 **Ctrl+C 로 껐나?** 켜 두면 테스트가 'already used' 로 시작을 못 합니다.

```
e2e-ts 폴더에서 npx playwright test -c playwright.mobile.config.ts 를 실행하면 폰 화면 테스트가 실패해.
web/app.py 의 화면 부분(HTML · CSS)만 고쳐서 통과시켜 줘.
- e2e-ts/ 의 테스트 · 설정 파일과 src/ 는 절대 수정하지 마.
- 화면 글자(라벨 · 버튼 이름)는 바꾸지 마.
- 고친 줄마다 어느 폰 AC 를 맞추려는 건지 한 줄씩 적어 줘.
- 끝나면 그 명령의 결과를 그대로 보여 줘.
```

웹 채팅이라면 상자 뒤에 `web/app.py` 의 `PAGE = """…"""` 부분과 실패 출력(`Expected` · `Received` 줄)을 붙여 넣습니다. AI 가 준 수정은 내가 `web/app.py` 에 옮기고 저장한 뒤 아래처럼 직접 돌립니다.

## 끝나고 직접 확인 (키트 루트 `sdd-qa-lab` 에서)
```bash
git diff --stat                    # 바뀐 건 web/app.py 하나여야 정상
cd e2e-ts; npx playwright test -c playwright.mobile.config.ts; cd ..   # 6 passed
```
AI 의 답에서 고친 줄마다 폰 AC 번호가 붙어 있는지도 봅니다. 줄과 AC 를 하나씩 맞춰 볼 수 있어야 합니다. 기본 실행(`npx playwright test`)은 폰 테스트와 상관없이 전과 같은 결과여야 합니다.

## 확인했으면 커밋
```bash
git add web/app.py
git commit -m "폰 화면 수정"
```

**가장 흔한 거짓 초록불**: 테스트의 44 를 낮추거나 설정 파일의 기기를 바꿔서 통과시키는 것. `git diff --stat` 에 `e2e-ts/` 가 보이면 `git checkout -- e2e-ts` 로 되돌리고 카드를 다시 보냅니다. 기대값(412px · 44px)은 사람이 명세에 정한 값입니다.

파이썬이 `py` 나 `python3` 로 실행되는 PC 라면 E2E 는 `PYTHON=py npx playwright test -c playwright.mobile.config.ts` (PowerShell: `$env:PYTHON="py"; npx playwright test -c playwright.mobile.config.ts`).
