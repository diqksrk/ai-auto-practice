# 실습⑤ (앱 팀) 우리 앱 흐름 하나 — Maestro 흐름 초안 + 화면 id 계약 표

앱으로 배포하는 팀은 실습⑤ 의 "어디서 볼지" 를 이 카드로 합니다. **실행은 하지 않습니다** (Maestro 는 Java · 에뮬레이터가 필요해 강의장에서는 무리). 산출물 두 개를 남겨 가서 팀에서 돌립니다.

먼저 `specs/TEMPLATE.md` 의 4절에 우리 흐름의 AC 5개를 씁니다. 그다음 **새 대화**에 아래를 붙여 넣습니다.

```
아래 AC 를 앱 E2E 테스트 도구 Maestro 의 흐름(YAML)으로 옮기려고 해. 아직 실행은 하지 않아.

1. 화면 요소 id 계약 표를 먼저 만들어 줘: | 화면 요소 | 테스트용 id | 지금 앱에 있나(모르면 [확인 필요]) |
   - id 는 화면 글자가 바뀌어도 안 바뀌는 이름으로 (예: signup-email, pay-submit). 5개 안팎.
   - 테스트에서만 쓰는 id 와, 여러 플랫폼(Android · iOS)이 같이 지켜야 하는 id 를 구분해 줘.
2. 그 id 만 써서 AC 중 화면으로 꼭 봐야 하는 1~2개를 Maestro YAML 로 써 줘.
   - 글자(tapOn: "확인")나 화면 좌표(point)로 누르지 마. id 로만.
   - 권한 팝업 · 지난 상태가 결과를 바꾸지 않게 launchApp 에 clearState · permissions 를 넣어 줘.
   - 마지막 줄은 AC 의 기대 결과를 assertVisible 로.
3. 나머지 AC 는 화면 말고 어디서 확인하면 되는지(API · 단위) 한 줄씩.
4. AC 를 테스트로 옮길 수 없으면 억지로 만들지 말고 어떤 AC 를 어떻게 고치면 되는지 알려 줘.

(여기에 AC 5개 붙여 넣기)
```

본뜰 예: `maestro/spec-example-8.yaml` — 같은 명세 예시 8 을 Maestro 로 쓴 것. 거기서 연도 칸을 좌표(`point`)로 누를 수밖에 없었던 것이 바로 "id 계약" 이 필요한 이유입니다.

**완료 기준**: [ ] id 계약 표 5개 안팎 · [ ] Maestro 흐름 1~2개, id 로만 · [ ] 나머지 AC 는 API · 단위로 · [ ] 팀에 가져갈 질문([확인 필요]) 목록

팀에 돌아가서: 계약 표의 id 를 앱 코드에 달고(Android `testTag` / `resource-id`, iOS `accessibilityIdentifier`), `maestro test 흐름.yaml` 로 한 번 돌린 뒤, 그 id 를 지우는 PR 은 막히게(CI) 합니다.
