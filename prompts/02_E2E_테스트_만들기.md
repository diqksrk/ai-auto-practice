# 실습③ (1/2) 명세로 E2E 테스트 만들기 (Playwright)

**새 대화**에서 시작하세요. AI 에게는 명세와 화면 객체만 줍니다. (앱 코드를 보면 코드의 가정을 테스트가 베낍니다)

```
아래 명세의 "4. 예시" 중에서, 사용자가 화면에서 직접 겪는 핵심 흐름 3개를 골라
Playwright 테스트로 만들어 줘.

- "쿠폰이 요금보다 큰 경우"(정답 표의 예시 8)는 반드시 넣고, 나머지 2개는 네가 골라. 오류가 나야 하는 예시는 빼.
  (화면 객체에 오류 메시지를 확인하는 방법이 없다)
- src/, web/, instructor/ 폴더는 읽지 마. 명세와 화면 객체만 보고 만든다.
- 파일: e2e-ts/tests/spec-examples.spec.ts
- 화면 조작은 반드시 e2e-ts/pages/charge-page.ts 의 ChargePage 만 써.
  (open / fill / calculate / expectCharge). 테스트 안에서 locator 를 직접 쓰지 마.
- expectCharge 에는 화면에 보이는 글자 그대로 넣어. 예: '1,666원', '0원'
- 테스트 이름에 명세 예시 번호를 넣어. 예: "명세 예시 8: 쿠폰이 요금보다 커도 0원"
- 기대값은 명세 표에서만 가져와. 네가 계산해서 바꾸지 마.
- 고른 3개가 왜 "화면에서 확인할 가치가 있는지" 한 줄씩 설명해 줘.
- 화면으로 확인할 수 없는 예시가 있으면 억지로 테스트를 만들지 말고, 어떤 예시가 왜 안 되는지 답변에만 적어 줘(파일은 만들지 마).
  (테스트로 옮길 수 없는 AC 는 AC 를 고칠 일이다. 고칠지는 내가 정한다)
- 테스트 파일만 만들고 멈춰. 테스트를 실행하거나 코드를 고치지 마 (실패를 내가 먼저 봐야 한다).

(여기에 완성한 specs/proration.md 붙여 넣기)
(여기에 e2e-ts/pages/charge-page.ts 붙여 넣기)
```
Claude Code · Cursor 처럼 저장소를 여는 도구라면 붙여 넣는 대신 "specs/proration.md 와 e2e-ts/pages/charge-page.ts 를 읽고" 라고 쓰면 됩니다.

## 만든 직후 커밋 (키트 루트 `sdd-qa-lab` 에서)
```bash
git add e2e-ts/tests/spec-examples.spec.ts
git commit -m "명세 기반 E2E 테스트"
```

## 실행 (키트 루트에서)
```bash
cd e2e-ts
npx playwright test          # 빨간불이 나오면 성공
npx playwright show-report   # 실패한 테스트 → Expected / Received · 스크린샷 · View Trace
cd ..
```
`show-report` 는 브라우저로 리포트를 연 채 터미널을 붙잡고 있습니다. 다 봤으면 터미널에서 **Ctrl+C** 로 끝내세요.
