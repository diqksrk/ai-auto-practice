# 실습③ (2/2) 테스트는 그대로, 코드만 고치기

**실습③ 을 시작하고 9분이 지났는데 아직 여기라면**: `cp instructor/proration_fixed.py src/billing/proration.py` → `git add src/billing/proration.py` → `git commit -m "정답 코드"` 로 넘어가세요. 다음 실습들이 이 상태에서 시작합니다.

```
e2e-ts 폴더에서 npx playwright test 를 실행하면 E2E 테스트가 실패해.
src/billing/proration.py 만 고쳐서 모든 테스트를 통과시켜 줘.

규칙:
- e2e-ts/tests/ 와 tests/ 의 파일은 절대 수정하지 마.
- 실패한 테스트가 명세(specs/proration.md)와 다르다고 생각되면, 고치지 말고 멈추고 나에게 물어봐.
- 테스트가 없는 곳이라도 명세를 어긴 코드가 보이면, 고치기 전에 규칙 번호(R1~)와 함께 목록으로 먼저 보여 줘.
- 돈 계산은 정수 연산만. float 금지.
- 끝나면 python -m pytest 와 npx playwright test 결과를 그대로 보여 줘.
```

시작 전에: codegen 시연 등으로 `python web/app.py` 를 따로 띄워 두었다면 **Ctrl+C 로 끄세요.** 테스트가 앱을 새로 띄워야 고친 코드로 돕니다.

## 끝나고 직접 확인 (키트 루트 `sdd-qa-lab` 에서)
```bash
python -m pytest                          # 단위 테스트 전부 통과?
cd e2e-ts; npx playwright test; cd ..     # E2E 전부 통과? (끝나면 루트로 돌아옴)
git diff --stat -- tests e2e-ts/tests     # 커밋한 뒤로 테스트 파일이 바뀌지 않았나? (아무것도 없어야 정상)
git diff --stat                           # 바뀐 건 src/billing/proration.py 하나여야 정상
```

## 확인했으면 커밋
```bash
git add src/billing/proration.py
git commit -m "명세대로 코드 수정"
```
(이걸 해 둬야 실습④ 에서 "동료 PR" 이 바꾼 것만 따로 보입니다)

**가장 흔한 거짓 초록불**: AI 가 테스트의 기대값을 코드에 맞게 바꿔서 통과시키는 것. `git diff` 로 꼭 확인하세요.

파이썬이 `py` 나 `python3` 로 실행되는 PC 라면 `python` 자리에 그 이름을 쓰세요. E2E 는 `PYTHON=py npx playwright test` (PowerShell: `$env:PYTHON="py"; npx playwright test`).
