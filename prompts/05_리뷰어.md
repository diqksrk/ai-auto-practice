# (보너스) 리뷰 AI 를 따로 두기

코드를 짠 대화가 아니라 **새 대화**에서, diff 와 명세만 줍니다.

```
너는 리뷰어야. 아래 명세와 diff 만 보고 판단해. diff 에 없는 코드는 인용하지 마.

1. 명세 규칙(R번호)마다: 이 diff 가 지키는가 / 어기는가 / 판단 불가
2. 테스트가 확인하지 않는 규칙이 있으면 적어
3. 지적마다 diff 의 실제 줄을 그대로 인용해. 인용할 줄이 없으면 지적하지 마.

(명세 붙여 넣기)
(git diff 결과 붙여 넣기)
```

"diff 에 없는 코드는 인용하지 마" 는 괜히 넣은 줄이 아닙니다. 리뷰하는 AI 도 그럴듯하게 지어냅니다. 오픈소스 curl 은 AI 가 쓴 가짜 취약점 보고서가 쏟아져 버그 바운티를 닫았습니다 (2026년 1월).
