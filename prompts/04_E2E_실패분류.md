# 실습④ 동료의 PR 이 E2E 를 깨뜨렸다 — AI 에게 "분류부터" 시키기

모든 명령은 **키트 루트(`sdd-qa-lab`)** 에서 실행합니다. 실습③ 의 코드 수정은 커밋해 둔 상태에서 시작하세요. (실습③ 을 못 끝냈으면 `cp instructor/proration_fixed.py src/billing/proration.py` → `git add src/billing/proration.py` → `git commit -m "정답 코드"` 후 시작) 따로 띄운 `python web/app.py` 가 있으면 Ctrl+C 로 끄세요.

## 1. 동료의 PR 적용 → 바로 커밋
```bash
python tools/lab4_change.py               # 동료의 PR: "화면 문구 정리 + 쿠폰 계산 리팩터링"
git add web/app.py                        # 동료 PR 이 바꾼 파일만
git commit -m "동료 PR"                   # 여기서부터 바뀐 것만 보이게
python -m pytest                          # 단위 테스트는?
cd e2e-ts; npx playwright test; cd ..     # E2E 는?
```

## 2. 분류부터 시키기
```
E2E 테스트가 실패했어. 아무것도 고치기 전에, 실패한 테스트마다 원인을 아래 넷 중 하나로 분류하고
근거(에러 메시지, 스크린샷/트레이스에서 본 화면)를 보여 줘.

- 화면 변경 : 버튼·칸 이름 같은 화면이 바뀌어서 테스트가 요소를 못 찾음
- 제품 버그 : 화면은 그대로인데 결과 값이 명세와 다름
- 불안정    : 다시 돌리면 통과하는 타이밍 문제
- 환경      : 서버가 안 떴거나 네트워크 문제

그다음 규칙대로만 고쳐:
- 화면 변경이면 e2e-ts/pages/ 의 위치 정보만 고친다. tests/ 의 기대값은 건드리지 않는다.
- 제품 버그면 테스트는 절대 고치지 않는다. 명세의 어느 규칙(R번호)을 어겼는지 쓰고, 원인이 되는 코드를 찾아 고친다.
- 기대값은 specs/proration.md 에서만 온다.
- 넷 중 어디에도 안 맞거나 명세 자체가 틀려 보이면, 아무것도 고치지 말고 멈춰서 근거와 함께 나에게 물어봐.
- 하나를 고칠 때마다 다시 돌려. 새로 실패하는 테스트가 나오면 그것도 고치기 전에 다시 분류부터.
- 끝나면 npx playwright test 결과를 그대로 보여 줘.

(여기에 specs/proration.md 붙여 넣기)
```
화면이 바뀐 실패가 앞을 가리고 있으면 뒤에 숨은 실패는 한 번 고친 뒤에야 보입니다. 그래서 "고칠 때마다 다시 돌리고, 다시 분류".
(실습③-2 에서 API 테스트를 만들었다면 `api-examples` 의 예시 8 이 처음부터 `amount: -4000` 으로 빨갛습니다. 화면 문구가 바뀌어도 API 테스트는 그대로 돌아서 제품 버그를 먼저 보여 줍니다 — 층마다 테스트를 나누는 이유)

## 3. 확인
```bash
git diff --stat                           # "동료 PR" 커밋 이후 바뀐 것: e2e-ts/pages/ (위치 정보) + web/app.py (버그 수정) 이어야 정상
git diff -- e2e-ts/tests tests            # 아무것도 없어야 정상 (기대값을 안 건드렸다)
cd e2e-ts; npx playwright test; cd ..     # 전부 통과
```
앱 팀이라면: 방금 고친 `getByLabel('구독료(원)')` 자리가 앱의 접근성 id 자리입니다. 글자가 아니라 id 로 찾았으면 화면 변경 실패 4개는 처음부터 없었습니다 — 앱 E2E 가 id 를 '계약' 으로 두는 이유.

## (강사 시연) 분류 없이 "그냥 고쳐줘" 하면?
강의에서는 강사 화면으로 봅니다. 혼자 해 볼 때는 2번 전에 아래를 시켜 보고, `git diff` 로 무엇을 고쳤는지 본 뒤 `git checkout -- .` 로 되돌리세요.
```
E2E 테스트가 깨졌어. 통과하게 고쳐줘.
```
눈여겨볼 것: 기대값을 -4,000원으로 바꾸기 / 화면 문구를 '월 요금'으로 되돌려 동료의 변경을 없애기 / 화면 쪽 쿠폰 계산에 max(0, …) 만 덧대기. 셋 다 테스트는 초록이 되지만 옳은 수정이 아닙니다.
(max(0, …) 가 틀린 이유: 화면 쪽으로 옮긴 쿠폰 계산은 정률 0~100% 검사(R6)도 빠뜨렸습니다. 150% 쿠폰이 오류가 아니라 0원으로 통과됩니다. 계산은 계산 모듈에 두는 게 맞는 수정입니다)
(이 저장소의 AGENTS.md 가 "분류 먼저"를 이미 말하고 있어서, Claude Code 처럼 AGENTS.md 를 읽는 도구는 그냥 시켜도 분류부터 할 수 있습니다. 웹 채팅에서 더 잘 드러납니다)

끝나면 `python tools/lab4_change.py --undo` 로 web/app.py 를 PR 적용 전으로 되돌릴 수 있습니다. e2e-ts/pages/ 를 고쳤다면 `git checkout -- e2e-ts/pages` 도 같이.
